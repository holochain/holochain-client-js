# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with
code in this repository.

## What this is

`@holochain/client`: TypeScript client for the Holochain Conductor API. See
`README.md` for what it is and version compatibility. Published from `lib/`
(compiled by `tsc`); `src/` is the only source of truth.

## Commands

```bash
npm run build:lib          # rimraf lib && tsc -p tsconfig.build.json
npm run build:docs         # api-extractor + api-documenter -> docs/*.md
npm run build              # both of the above
npm run lint               # eslint --fix over src, test, eslint.config.cjs
npm run format             # prettier over src/**/*.ts and test/**/*.ts
npm test                   # vitest run (all tests, serial)
npx vitest run <pattern>   # single file, e.g. `npx vitest run signal-decode`
npx vitest run -t "<name>" # single test by title
npm run regen:types        # regenerate ts-rs wire types from Holochain (Nix)
```

CI lint runs `npm run lint:ci` (same as `lint` but without `--fix`);
prettier violations are lint errors (`plugin:prettier/recommended`).

### Tests

Two kinds live under `test/`:

- Pure unit tests at `test/*.test.ts` (`dht-ops`, `signal-decode`, `tauri`).
  No conductor needed; run with plain `npx vitest run`.
- Integration tests at `test/e2e/*.test.ts`. They spawn `hc sandbox`,
  `holochain` and `kitsune2-bootstrap-srv` from `PATH` and install the
  fixture hApp at `test/e2e/fixture/test.happ`. Requirements:

  ```bash
  nix develop            # provides holochain, hc, bootstrap-srv, rust, node
  ./build-fixture.sh     # cargo-builds the fixture zomes, packs test.happ
  npm test
  ```

  `.envrc` has `use flake`, so direnv users get the shell automatically.
  Vitest is configured with `fileParallelism: false` and a 60s timeout
  because every e2e file shares the sandbox conductor lifecycle
  (`withApp` in `test/e2e/common.ts` creates/tears down a conductor per test).

`npm run test:app-agent` and `npm run test:utils` are pattern shortcuts for
`app-websocket` and `utils` e2e files.

### Docs

`docs/` is generated by `npm run build:docs` from the built `lib/` d.ts files
via API Extractor. Only symbols tagged `@public` in TSDoc appear; API
Extractor is configured to error on missing/invalid TSDoc, so new exported
symbols need a doc comment with `@public` (or `@internal`). The PR template
asks that docs be regenerated when the public API changes.

## Architecture

### Public entry

`src/index.ts` re-exports everything: `api/`, `hdk/`, `utils/`, `types.ts`,
`client-types.ts`, and only the environment-detection surface of
`environments/tauri.ts` (`isTauriHolochain`,
`getTauriHolochainEnvironment`). Anything not re-exported there is outside
the semver contract.

### Request pipeline

Every Admin/App call is `{ type: "<tag>", value: <payload> }` msgpack over
a Holochain `WireMessage` (`{ id, type: "request"|"response"|"signal",
data }`).

- `src/api/client.ts` `WsClient`: raw websocket transport (Emittery for
  `signal` events, pending-request map keyed by incrementing id). Handles
  App-API `authenticate`, and transparent reconnect + re-auth on a closed
  socket using the cached token (concurrent reconnects are deduped).
  Decodes responses with `holoHashMapKeyConverter` so byte-keyed maps become
  Base64 keyed objects.
- `src/api/common.ts`: `requesterTransformer` wraps a raw requester with a
  tag plus optional input/output `Transformer`; `catchError` turns
  `{ type: "error" }` responses into `HolochainError`; `promiseTimeout`
  applies `DEFAULT_TIMEOUT` (60s).
- `src/api/admin/websocket.ts` `AdminWebsocket` and
  `src/api/app/websocket.ts` `AppWebsocket`: one method per API request,
  each built with `requesterTransformer`. `AppWebsocket.callZome` runs the
  request through a `CallZomeTransform` that signs the zome call
  (`signZomeCall`, or a host signer injected on `window` by
  Launcher/Electron), computes nonce/expiry, and decodes the msgpack
  response payload.
- `src/api/zome-call-signing.ts`: in-memory store of `SigningCredentials`
  per cell (`setSigningCredentials` / `getSigningCredentials`);
  `AdminWebsocket.authorizeSigningCredentials` populates it via a cap grant.

### Transports and environments

`AppWebsocket` depends on the `AppClientTransport` interface
(`src/api/app/client-types.ts`), not on `WsClient` directly. Two
implementations:

- `WsClient` (websocket, default).
- `TauriAppTransport` (`src/api/app/tauri-transport.ts`): sends the same
  msgpack payloads over Tauri IPC (`plugin:<name>|app_request`) when
  `isTauriHolochain()` detects the `__HC_TAURI_HOLOCHAIN__` window marker.
  `AppWebsocket.connect()` picks it automatically; no app token is used.

`src/environments/launcher.ts` reads `__HC_LAUNCHER_ENV__` (ports, app id,
token) and `__HC_ZOME_CALL_SIGNER__` from `window`, so `connect()` works with
no arguments inside Holochain Launcher. Signal decoding shared by both
transports lives in `src/api/app/decode.ts`.

### Generated types (do not hand-edit)

The wire types are exported from Holochain's Rust source with `ts-rs` into
`src/generated/` (`types.ts`, `api/admin/types.ts`, `api/app/types.ts`,
`hdk/*.ts`), mirroring ts-rs's own output tree. `src/generated/` holds
nothing but that output — no hand-written companions ever live there — so
`npm run regen:types` wipes and replaces the whole directory. Everything
else in `src/` (the `client-types.ts` files, `src/hdk/index.ts`,
`src/utils/*`, `src/api/*/index.ts`) is hand-written and re-exports from
`src/generated/` for the rest of the codebase to import.

`npm run regen:types` runs `nix develop -c hc export-ts-bindings --out-dir
src/generated`: `nix develop` builds Holochain's `hc` with its opt-in
`ts_rs` and `unstable-countersigning` features, against the holochain
revision pinned in `flake.lock` (this is the `hc` on `PATH` in the dev
shell, not a separate binary), and its `export-ts-bindings` subcommand
wipes and recreates `--out-dir` itself.

The `regen-types-check` job in `.github/workflows/test.yml` runs this in CI
and fails `ci_pass` if the committed types drift from a fresh regeneration.

### Fixture zomes

`Cargo.toml` at the root is a workspace for the test zomes only
(`test/e2e/fixture/zomes/{integrity,coordinator}/foo`,
`test/e2e/fixture2/coordinator2`), built to `wasm32-unknown-unknown` by
`build-fixture.sh`.

## Conventions

- ESM only (`"type": "module"`); relative imports carry `.js` extensions
  even in `.ts` files (NodeNext resolution). Node `>=22`.
- Wire-facing field names stay snake_case to match Rust (`cell_id`,
  `installed_app_id`, `zome_name`); JS-side helpers are camelCase.
- **NEVER write to `CHANGELOG.md`.** It is autogenerated on release from
  Conventional Commit messages by the release workflow. Do not add entries,
  fix typos, or touch it in any commit or PR.
- Releases: run the "Prepare Release" GitHub Actions workflow on `main`,
  merge the generated PR; the merge publishes to npm.
- Plans/design notes live in `.claude/plans/` (git-excluded locally); do not
  commit them.
- Nix CI jobs use `cachix/cachix-action` (`holochain-ci` cache) only. Don't
  add `nix-community/cache-nix-action` or similar local nix-store caching
  next to it; it duplicates what cachix already serves and adds purge
  logic to maintain for no real speedup.
